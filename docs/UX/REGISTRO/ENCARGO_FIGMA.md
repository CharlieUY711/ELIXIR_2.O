# Encargo a Figma - Diseño Visual del Registro Unificado

**Fecha**: 2025-01-27  
**Tipo**: Encargo de Diseño Visual  
**Versión**: 1.0  
**Estado**: En ejecución

---

## 1. Contexto

- Registro conceptual, UX, estados, backend y manejo de datos están cerrados
- D0 (alineación UX ↔ manejo de datos) completado
- Se avanza a diseño visual (Figma) como paso D
- Figma actúa solo como ejecutor visual

---

## 2. Alcance del Diseño

### 2.1. Ubicación del Diseño

El diseño se realizará:
- En el **MISMO archivo/proyecto Figma** donde existe el Catálogo
- En una nueva sección/página llamada:
  **"02 · Registro Unificado"**

### 2.2. Identidad Visual

Figma debe:
- Usar **exactamente la misma identidad visual** del Catálogo
- No redefinir colores, tipografías ni spacing
- No proponer mejoras de UX

### 2.3. Pantallas a Diseñar

Únicamente las siguientes pantallas:

- **R0 · Entrada**
- **R1 · WhatsApp**
- **R2 · OTP**
- **R3 · Identidad Provisional**
- **R4 · Selección de Rol**

---

## 3. Fuentes Únicas de Verdad

Figma debe basarse exclusivamente en:

- `/docs/UX/REGISTRO/`
- `/docs/UX/REGISTRO/ARTEFACTOS/`
- `/docs/DATA_HANDLING/`

**No debe consultar ni basarse en otras fuentes.**

---

## 4. Restricciones Explícitas

Figma **NO debe**:

- Agregar pasos
- Mover gates
- Introducir nuevas decisiones
- Mencionar proveedores
- Sugerir anonimato absoluto
- Sugerir custodia de datos

---

## 5. Resultado Esperado

- Diseño visual coherente con documentación
- Registro listo para implementación futura
- Sin contradicciones con backend ni políticas de datos

---

## 6. Notas Adicionales

Este encargo es puramente visual. Todas las decisiones de UX, flujo, estados y manejo de datos ya están definidas y cerradas. Figma debe limitarse a ejecutar el diseño visual respetando la identidad existente del Catálogo.
